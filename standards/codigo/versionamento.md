# Versionamento de código

> **Situação:** Proposto. 

Adotar commits descritivos vinculados a história/microentrega, branches e pull requests conforme o repositório específico. Releases devem identificar versão, mudanças, dependências e evidências de teste. Não commitar segredos, credenciais ou dumps com dados pessoais. A estratégia de branch e numeração semântica por produto permanece a definir.
